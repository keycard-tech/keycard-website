# Integrate a Wallet with Keycard Shell

Keycard Shell works with software wallets the same way as other QR-based signers: the wallet builds transactions and broadcasts them; Shell verifies and signs them with the Keycard inside. If your wallet already supports EIP-4527 animated QR codes or PSBT-over-UR, supporting Shell requires little to no extra work.

Two transports are available:

- **QR codes (air-gapped)** — the default flow, fully offline.
- **USB** — an APDU-like protocol over USB HID, for desktop wallets that prefer a cable.

## Trust model

- **Keycard holds the keys.** Shell talks to the Keycard over the ISO-7816 smartcard interface and never stores private keys.
- **User confirmation is required.** Requests coming from QR or USB are displayed on-device and require explicit approval.
- **Air-gapped by default.** QR workflows are fully offline. USB data transfer is optional and can be disabled in settings.

## QR integration (EIP-4527 + UR)

Shell uses the [EIP-4527](https://eips.ethereum.org/EIPS/eip-4527) animated QR format with [Blockchain Commons UR](https://developer.blockchaincommons.com/ur/) encoding for sign requests and responses — the same standards used across the QR-signer ecosystem.

The flow for a wallet:

1. **Account import** — Shell exports accounts as `crypto-multi-accounts`; your wallet scans the QR and derives addresses from the xpub.
2. **Sign request** — your wallet displays the payload as an animated QR (`eth-sign-request`, `crypto-psbt` or `btc-sign-request`); the user scans it with Shell's camera.
3. **Signature** — Shell displays the decoded transaction for approval, signs with the Keycard, and returns the signature as a QR (`eth-signature`, signed PSBT, `btc-signature`) that your wallet scans back.

The exact payloads Shell accepts are specified in the [Shell API reference](/developers/shell-api).

## USB integration

When USB data is enabled, Shell enumerates as a USB HID device and speaks an APDU-like protocol with commands for account export, transaction signing (ETH, EIP-712, PSBT) and device information. See the [Shell API reference](/developers/shell-api) for the protocol details.

## Clear signing

Shell decodes what it signs: contract calls, ERC-20 transfers and EIP-712 messages are displayed in human-readable form using an on-device database of chains, token metadata and contract ABIs. If your dApp's or protocol's contracts are not yet decoded, [add their ABIs](/developers/contribute) to the open database — it improves the experience for every wallet.

## Bitcoin-only wallets

There is no separate "bitcoin-only" firmware, and none is needed: Bitcoin wallets integrate through standard PSBT flows (QR/UR or USB) and simply never touch the Ethereum features.
