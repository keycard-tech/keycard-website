# INIT

* CLA = 0x80
* INS = 0xFE
* P1 = 0x00
* P2 = 0x00
* Data = the encrypted payload
* Response SW = 0x9000 on success, 0x6A80 if the data is invalid, 0x6D00 if the applet is already initialized
* Capability: Credentials management

This command is only available when the applet is in pre-initialized state and successful execution brings the applet to the initialized state. It stores the user authentication credentials — nothing more. Creating a wallet is a separate step, done with [LOAD KEY](/developers/apdu/loadkey) or [GENERATE KEY](/developers/apdu/generatekey).

Retry limits are validated against the ranges 2–10 for the PIN and 3–12 for the PUK. The duress PIN works as described in [VERIFY PIN](/developers/apdu/verifypin).

## Transport

The payload never travels in the clear. The client generates a throwaway secp256k1 key pair, performs EC-DH with the card and encrypts the payload with AES-CBC using ISO/IEC 9797-1 Method 2 padding and a random IV. The [secure channel](/developers/apdu/opensecurechannel) is then established normally.

Before 4.0 the one-shot encryption key was derived from the card's ephemeral public key returned by **SELECT**; since 4.0 **SELECT** returns the identity certificate instead and the initialization payload is carried over the same secure channel used by every other command. The command is also available before the card holds a PIN, which is what makes the "is this card initialized?" check in the **SELECT** status byte useful.

After successful execution this command cannot be executed again.
