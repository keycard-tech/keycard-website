# Build Your Own Keycard

If you have a blank JavaCard 3.0.5+ card (readily available for purchase on the web) you can build your own Keycard. This is especially useful for developers who want to contribute to the project and/or experiment with it.

Please note that cards built this way will not carry a certificate from the Keycard certification authority. Since applet 4.0 the applet refuses every command until an identity is provisioned, so you must load a self-signed or test certificate before the card will respond — see [Provisioning an identity](#provisioning-an-identity). Wallets will also warn that the card is not from a CA they trust; for a card you built yourself you can safely pin its identity instead.

## Compiling and installing from source

Compiling and installing from source is probably the best way to proceed, since this will also leave you with a working development environment for all your experiments.

### Requirements

- Linux, Windows or Mac computer
- OpenJDK 11 (this specific version is required — newer JDKs are not compatible with the JavaCard build tools)
- A Javacard 3.0.5+ smartcard with T=1 and SCP02 support. Cards of the JCOP4 family are known to work well. We sell and ship this type of keycards for developers on [our shop](https://keycard.tech/products/keycard-for-developers). For detailed requirements about the card, we recommend to check the [card requirements](https://github.com/keycard-tech/status-keycard#what-kind-of-smartcards-can-i-use) in the keycard github repository.
- A standard PCSC smartcard reader

### Setting up OpenJDK 11

#### macOS

```bash
brew install openjdk@11
export JAVA_HOME=/opt/homebrew/opt/openjdk@11/libexec/openjdk.jdk/Contents/Home
export PATH="/opt/homebrew/opt/openjdk@11/bin:$PATH"
java -version   # should show openjdk version "11.0.x"
```

#### Linux (Debian/Ubuntu)

```bash
sudo apt update
sudo apt install openjdk-11-jdk pcscd libpcsclite-dev
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
```

#### Windows

Download and install OpenJDK 11 from [Adoptium](https://adoptium.net/temurin/releases/?version=11) (select Windows, x64, JDK, `.msi`). You can either 
- check the option to set JAVA_HOME during installation, or 
- Open a new terminal and run command `set JAVA_HOME=C:\Program Files\Eclipse Adoptium\jdk-11`

### Installation steps

1. Plugin your PCSC reader and insert the card. Make sure no other PCSC reader (or Yubikey) is plugged in
2. Open your terminal app of choice
3. Clone the Keycard repo with the command `git clone --recurse-submodules https://github.com/keycard-tech/status-keycard`
4. Enter the repository with `cd status-keycard`
5. Build and install the applet:
   - macOS / Linux: `./gradlew install`
   - Windows: `gradlew.bat install`
6. When you see `BUILD SUCCESSFUL`, the applets are installed. The install task loads both the `keycard-math` support package (required since 4.0) and the Keycard package, then installs the Keycard, NDEF, Cash and Ident applets.
7. [Provision an identity](#provisioning-an-identity) before initializing the card, otherwise every command is rejected.

This assume that the smartcard you are using uses the default GlobalPlatform keys (true for most cards sold online) or the Keycard development keys (if you bought a development card from us). In case you already played with the card and changed the ISD keys yourself, follow the below step. 

### Provisioning an identity

Since 4.0 the Keycard applet will not answer anything — not even SELECT — until a valid identity certificate has been loaded, because the secure channel authenticates the card with that key. The [Keycard CLI](https://github.com/keycard-tech/keycard-cli) does this for you:

```bash
# Generate a random identity and a certificate from the test CA, then load it
keycard load-ident --test
```

This is fine for development. The card then works with the CLI and SDKs when they are told to trust the test CA, and with wallets when they are given the card identity to pin. For a card you intend to use for real, generate the certificate under your own CA and load it with `keycard load-ident --hex`, and make sure the CA public key is the one your clients trust.

Cards bought from us already carry a production identity and need none of this.

### Alternative installations steps

1. Follow step 1-4 above
2. Execute `./gradlew convertJavacard`
3. Find the file `keycard.cap` file in the `build` directory.
4. Install the cap file using your favorite [GlobalPlatform management tool](https://github.com/martinpaljak/GlobalPlatformPro)
5. Install the Keycard applet, making sure you assign instance AID `A00000080400010101`
6. Optionally install the other applets in the cap file, you can find all AIDs [here](https://github.com/keycard-tech/status-keycard-java/blob/master/lib/src/main/java/im/status/keycard/applet/Identifiers.java)

### Locking the card

After following the installation steps above your card will still be open to changes. This is very useful during development because you can repeat the installation steps as many times as you want to test changes you made to the app. To make your card immutable, in a way similar to what we do you need to do 2 things:

1. Change the ISD keys to random ones. If you store these you will still be able to reinstall the applet or update to a new version. Since only you will have the keys this is reasonably safe, however you would have to store these keys securely.
2. Bring the card from the OP_READY lifecycle state to the SECURED one

you can perform these two steps using either your favorite GlobalPlatform management tool or by following these two steps

1. `cd status-keycard`
2. `./gradlew lock`

**NOTE: THIS PROCEDURE IS NOT REVERSIBLE. THE AUTOMATED LOCKING TOOL DOES NOT PRINT OR STORE THE RANDOMLY GENERATED KEYS ANYWHERE**
